# چک‌لیست آماده‌سازی و آزمون هوشیار در Cloudflare Pages

این راهنما فقط برای **Cloudflare Pages** است. هیچ مرحله‌ای از آن نیازمند ساخت، تغییر، خاموش‌کردن یا استقرار Cloudflare Workers نیست.

## ۱) تنظیمات Build در Pages

- اتصال Git به مخزن `alimozaffari1000-cyber/houshyar-ai`
- شاخه آزمایشی برای Preview: `feature/local-store-discovery-ui`
- Build command: `npm run build`
- Build output directory: `dist`
- Root directory: ریشه مخزن
- فایل پیکربندی مخزن `wrangler.toml` مقدار `pages_build_output_dir = "./dist"` را دارد.
- برای انتشار Pages از اتصال Git/روند استقرار Pages استفاده شود؛ دستور `wrangler deploy` مخصوص این روند نیست و نباید اجرا شود.

## ۲) Secrets سمت سرور Pages

کلیدها را فقط در تنظیمات Environment Variables و از نوع Secret در پروژه Pages وارد کنید؛ هرگز در کد مرورگر یا Git قرار ندهید.

| متغیر | وضعیت |
|---|---|
| `GROQ_API_KEY` | اختیاری؛ یکی از ارائه‌دهندگان AI باید فعال باشد |
| `OPENAI_API_KEY` | اختیاری؛ برای استفاده از OpenAI |
| `CLAUDE_API_KEY` | اختیاری؛ برای استفاده از Anthropic |
| `AI_DEFAULT_PROVIDER` | اختیاری؛ یکی از `groq`، `openai` یا `anthropic` |
| `OPENAI_MODEL` | اختیاری؛ مقدار پیش‌فرض کد `gpt-6-astra` است |
| `OPENAI_MODEL_FAST` / `OPENAI_MODEL_DEEP` / `OPENAI_MODEL_CREATIVE` | اختیاری؛ مدل‌های اختصاصی هر حالت |
| `GROQ_MODEL` / `GROQ_MODEL_VISION` | اختیاری؛ مدل متن و مدل بینایی Groq |
| `CLAUDE_MODEL` | اختیاری؛ مدل Anthropic |

مدل‌های API و دسترسی آن‌ها به حساب ارائه‌دهنده وابسته‌اند. استفاده از OpenAI API صورتحساب و کلید API مستقل می‌خواهد و با اشتراک ChatGPT یکی نیست.

## ۳) Bindingهای Pages برای قابلیت‌های فروشگاهی

این موارد فقط در محیط Preview و قبل از هر انتشار بررسی شوند:

- D1 binding با نام دقیق `DB` به پایگاه داده آزمایشی متصل شود.
- R2 binding با نام دقیق `MEDIA_BUCKET` به یک bucket خصوصی آزمایشی متصل شود.
- دسترسی عمومی `r2.dev` برای تصاویر خصوصی فروشندگان فعال نشود.
- متغیرهای فعال‌سازی احراز هویت، سهمیه و محدودسازی نرخ فقط پس از اتصال و آزمون وابستگی‌هایشان روشن شوند؛ از جمله `AUTH_ENABLED`، `CHAT_QUOTA_ENABLED` و `CHAT_RATE_LIMIT_ENABLED`.
- هیچ Migration روی پایگاه داده Production اجرا نشود.

## ۴) ترتیب مهاجرت پایگاه داده آزمایشی

1. از D1 آزمایشی نسخه پشتیبان بگیرید.
2. وضعیت جدول‌ها و Migrationهای اعمال‌شده را بررسی کنید.
3. Migrationهای `0001` تا `0008` را به ترتیب روی D1 آزمایشی اجرا کنید؛ فقط Migrationهای اعمال‌نشده.
4. آزمون‌های سفارش، گالری رسانه، موجودی و پذیرش سفارش را اجرا کنید.
5. تأیید کنید پذیرش سفارش در صورت موجودی ناکافی به‌صورت اتمیک rollback می‌شود.
6. نتیجه را ثبت کنید؛ بدون تأیید انسانی هیچ Migrationای به Production منتقل نشود.

## ۶) معیار عبور به انتشار

انتشار فقط وقتی قابل بررسی است که:

- سه گردش‌کار Guardian، Security Watch و Quality روی آخرین commit موفق باشند.
- آزمون‌های خودکار و Build موفق باشند.
- تمام آزمون‌های Preview بالا با D1 و R2 آزمایشی تکمیل شوند.
- هیچ Secret در مخزن یا خروجی مرورگر افشا نشده باشد.
- مالک پروژه نتیجه را تأیید کند.

**ممنوع در این روند:** تغییر Workers، اجرای `wrangler deploy`، اعمال Migration روی Production، ادغام PR یا انتشار Production بدون تأیید صریح مالک.
