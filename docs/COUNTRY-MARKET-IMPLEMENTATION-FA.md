# پیاده‌سازی مرحله اول بازار داخلی کشورمحور هوش‌یار

## دامنه این مرحله

این تغییر، نخستین لایه اجرایی تجارت داخلی کشورمحور را روی بازارگاه موجود اضافه می‌کند؛ بازارگاه موازی ساخته نمی‌شود.

### تغییرات

- Migration شماره 0008 جدول `country_market_configs` را برای پیکربندی نسخه‌دار بازار هر کشور اضافه می‌کند.
- وضعیت پیش‌فرض هر کشور `research` است؛ هیچ کشوری با این migration به‌صورت خودکار live نمی‌شود.
- به `merchant_stores` ستون اختیاری `country_code` اضافه می‌شود تا کشور محل فعالیت اعلام‌شده فروشگاه ثبت شود.
- درخواست ثبت فروشگاه می‌تواند `countryCode` دوحرفی ISO را دریافت کند.
- فروشنده می‌تواند کشور فعالیت فروشگاه خود را از طریق پروفایل به‌روزرسانی کند؛ update همچنان با شرط مالکیت `id AND user_id` انجام می‌شود.
- دو endpoint جست‌وجوی موجود، پارامتر اختیاری `country` را می‌پذیرند:
  - `GET /api/stores?country=AZ`
  - `GET /api/store/products?country=AZ`
- جست‌وجوی کشورمحور فقط فروشگاه‌هایی را برمی‌گرداند که کشورشان با درخواست تطبیق دارد و رکورد همان کشور در `country_market_configs` وضعیت `live` دارد.
- کد کشور نامعتبر با پاسخ 400 رد می‌شود.

## مرزهای ایمنی و دقت

- `countryCode` اعلام کشور فعالیت فروشگاه است، نه اثبات موقعیت مکانی کاربر، هویت حقوقی یا مجوز فعالیت.
- بررسی دوحرفی بودن کد، جایگزین فهرست مرجع کامل ISO یا بررسی حقوقی نیست.
- این مرحله مالیات، قوانین مصرف‌کننده، احراز هویت تجاری، پرداخت، ارسال یا مجوزهای واردات/صادرات را خودکار نمی‌کند.
- کشورها تا زمان بررسی و فعال‌سازی کنترل‌شده، در وضعیت غیر live باقی می‌مانند.
- endpointهای جست‌وجوی قدیمی بدون پارامتر `country` رفتار قبلی را حفظ می‌کنند.
- کشور بازار نباید جایگزین کنترل دسترسی tenant یا مالکیت فروشگاه شود.

## API examples

ثبت فروشگاه:

```json
{
  "name": "نمونه فروشگاه",
  "slug": "sample-store",
  "description": "توضیحات فروشگاه",
  "countryCode": "AZ"
}
```

جست‌وجوی محصولات در یک بازار داخلی فعال:

```http
GET /api/store/products?country=AZ&q=apple
```

اگر بازار AZ در وضعیت `live` نباشد، نتیجه جست‌وجوی کشورمحور خالی خواهد بود؛ این رفتار fail-closed و عمدی است.
