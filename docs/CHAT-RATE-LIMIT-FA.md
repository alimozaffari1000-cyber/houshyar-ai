# کنترل نرخ درخواست چت

این قابلیت در API چت پیاده‌سازی شده، اما به‌صورت پیش‌فرض خاموش است تا قبل از اتصال و مهاجرت D1 رفتار سایت تغییر نکند.

## فعال‌سازی پس از آماده‌سازی D1

1. ابتدا migration شماره 0001_identity_usage_security.sql را روی دیتابیس مقصد اجرا کنید.
2. در Cloudflare Pages/Workers یک D1 binding با نام دقیق DB متصل کنید.
3. متغیر محیطی CHAT_RATE_LIMIT_ENABLED را روی true قرار دهید.
4. در صورت نیاز CHAT_RATE_LIMIT_PER_MINUTE را روی عددی بین 1 تا 120 تنظیم کنید؛ مقدار پیش‌فرض 20 درخواست در هر دقیقه برای هر IP است.
5. ابتدا در Preview آزمایش کنید و سپس تنظیم Production را تغییر دهید.

## رفتار امنیتی

- کلید محدودسازی با SHA-256 از IP ساخته می‌شود؛ IP خام در جدول محدودسازی ذخیره نمی‌شود.
- فقط هدر Cloudflare یعنی cf-connecting-ip استفاده می‌شود؛ هدرهای قابل جعل مانند x-forwarded-for مبنا نیستند.
- شمارنده با یک UPSERT اتمیک در D1 افزایش می‌یابد تا درخواست‌های هم‌زمان از شمارش عبور نکنند.
- درخواست مازاد پاسخ HTTP 429 و هدر Retry-After می‌گیرد.
- اگر محدودسازی فعال باشد اما D1 متصل نباشد یا خطا بدهد، درخواست به مدل ارسال نمی‌شود (fail-closed).
- این محدودیت فعلاً بر اساس IP است، نه حساب کاربری؛ با پیاده‌سازی احراز هویت، سهمیه کاربر نیز باید اضافه شود.
- جدول api_rate_limits باید به‌صورت زمان‌بندی‌شده پاک‌سازی شود؛ شاخص expires_at برای این کار آماده است.

## وضعیت

کد و تست‌ها اضافه شده‌اند. قابلیت تا زمان اتصال D1 و تنظیم متغیر محیطی فعال نیست. این تغییر به‌تنهایی به معنی فعال شدن D1 یا استقرار موفق در Cloudflare نیست.
