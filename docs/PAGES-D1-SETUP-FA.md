# راه‌اندازی دیتابیس هوش‌یار برای Cloudflare Pages

این راهنما فقط مربوط به **Cloudflare Pages، Pages Functions و D1** است. تنظیمات و استقرار Workers خارج از محدوده این پروژه است و نباید تغییر داده شود.

## معماری و اتصال‌ها

- خروجی رابط کاربری در `dist` ساخته و توسط Pages میزبانی می‌شود.
- APIهای پوشه `functions/api/` از binding با نام دقیق `DB` استفاده می‌کنند.
- تصاویر محصولات باید در یک R2 bucket خصوصی با binding به نام `MEDIA_BUCKET` نگهداری شوند؛ دسترسی عمومی `r2.dev` فعال نشود.
- Preview باید به دیتابیس آزمایشی و Production فقط به دیتابیس اصلی متصل باشد. این دو محیط نباید دیتابیس مشترک داشته باشند.

## ترتیب کامل migrationها

مخزن در حال حاضر هشت migration دارد و همه باید به ترتیب روی دیتابیس آزمایشی بررسی شوند:

1. `0001_identity_usage_security.sql` — کاربران، نشست‌ها، رویدادها و محدودیت نرخ.
2. `0002_daily_usage_quotas.sql` — سهمیه روزانه مصرف.
3. `0003_email_verification_password_reset.sql` — توکن‌های تأیید ایمیل و بازیابی رمز.
4. `0004_marketplace_foundation.sql` — فروشگاه‌ها و محصولات.
5. `0005_visual_try_on_foundation.sql` — دسته بصری محصول و فراداده تصاویر.
6. `0006_local_store_discovery.sql` — شهر، نشانی عمومی، مختصات و روش‌های تحویل فروشگاه.
7. `0007_marketplace_orders.sql` — درخواست سفارش و اقلام سفارش.
8. `0008_atomic_order_inventory.sql` — کسر اتمیک موجودی فقط هنگام پذیرش سفارش توسط فروشنده.

Migration شماره ۸ موجودی را هنگام ثبت درخواست خریدار رزرو نمی‌کند. اگر فروشنده سفارش را تأیید کند، trigger موجودی را کم می‌کند؛ اگر موجودی کافی نباشد، کل تغییر وضعیت و تمام تغییرات موجودی همان دستور باید rollback شوند.

## پیش‌نیازهای Staging

1. در Cloudflare Dashboard، از بخش D1 یک دیتابیس مجزا برای Staging بسازید.
2. در پروژه **Pages** به مسیر Settings → Functions → D1 database bindings بروید.
3. در محیط Preview، binding با نام `DB` را به دیتابیس Staging متصل کنید.
4. در پروژه Pages، binding خصوصی R2 با نام `MEDIA_BUCKET` را به bucket آزمایشی وصل کنید.
5. مطمئن شوید Preview به دیتابیس Production متصل نیست.
6. پیش از migration، از دیتابیس Staging نسخه پشتیبان بگیرید و وضعیت migrationهای ثبت‌شده را بررسی کنید.

## اعمال migration فقط روی Staging

از محیط مدیریتی مورداعتماد که Wrangler و دسترسی محدود Cloudflare در آن تنظیم شده است، ابتدا وضعیت را ببینید:

```bash
npx wrangler@4 d1 migrations list houshyar-ai-staging --remote
```

سپس فقط پس از تطبیق نام دیتابیس و تأیید اینکه مقصد واقعاً Staging است، migrationهای ثبت‌نشده را اجرا کنید:

```bash
npx wrangler@4 d1 migrations apply houshyar-ai-staging --remote
npx wrangler@4 d1 migrations list houshyar-ai-staging --remote
```

دستور apply همه migrationهای ثبت‌نشده در پوشه migrations را اعمال می‌کند. خروجی فهرست باید هر هشت migration را به ترتیب نشان دهد. اگر وضعیت دیتابیس نامشخص است، خطا می‌دهد، یا migrationای قبلاً دستی اجرا شده اما ثبت نشده است، ادامه ندهید؛ ابتدا schema و تاریخچه را با دقت تطبیق دهید. فایل‌های migration را روی دیتابیس دارای داده حذف یا بازنویسی نکنید.

## آزمون‌های لازم روی Pages Preview

پس از اتصال Staging و deploy شدن Preview، موارد زیر را با حساب‌های آزمایشی بررسی کنید:

- ثبت‌نام، ورود، نشست و بازیابی حساب.
- ساخت فروشگاه، تأیید مدیریتی و جداسازی داده فروشندگان.
- انتشار محصول و نمایش عمومی فقط محصولات مجاز فروشگاه فعال.
- بارگذاری، مشاهده و حذف تصویر از R2 خصوصی؛ محصول منتشرنشده یا فروشگاه غیرفعال نباید رسانه عمومی داشته باشد.
- جست‌وجوی فروشگاه بر اساس شهر و روش تحویل.
- ثبت درخواست سفارش، مشاهده تاریخچه خریدار و مدیریت سفارش فروشنده.
- پذیرش دو سفارش رقیب برای آخرین واحد؛ فقط یک سفارش پذیرفته شود.
- شکست پذیرش چندمحصولی باید تمام تغییرات موجودی را rollback کند.
- رد سفارش و تکمیل سفارش نباید موجودی را دوباره کم کند.
- خطاها و logها نباید رمز، session token یا کلید API را افشا کنند.

تست SQLite در CI تمام هشت فایل migration را به ترتیب روی دیتابیس موقت اجرا می‌کند و رفتار trigger موجودی را می‌سنجد. این تست جایگزین آزمون سازگاری D1 در Preview نیست؛ هر دو لازم‌اند.

## Production — فعلاً اجرا نشود

این راهنما مجوز اعمال migration روی Production نیست. تا زمانی که Staging، Pages Preview، پشتیبان‌گیری و بازیابی تأیید نشده‌اند، روی دیتابیس اصلی هیچ migrationای اجرا نکنید. پس از تأیید جداگانه و صریح انتشار، ابتدا backup قابل‌بازیابی تهیه و سپس برنامه مهاجرت Production تدوین شود.

## محدودیت دسترسی

این مخزن به‌تنهایی به حساب Cloudflare یا دیتابیس‌های شما دسترسی مدیریتی نمی‌دهد. هیچ migration راه‌دوری از این تغییرات اجرا نشده است. کلید API یا رمز عبور را در Git، گفتگو یا فایل‌های پروژه قرار ندهید. این تغییرات هیچ تنظیم یا استقرار Workers را انجام نمی‌دهند.
