# فضای پروژه‌های شخصی هوش‌یار

## قابلیت‌های پیاده‌سازی‌شده در شاخه توسعه

- هر حساب می‌تواند حداکثر ۵۰ پروژه ایجاد کند.
- هر پروژه عنوان ۱ تا ۸۰ نویسه و توضیح اختیاری حداکثر ۵۰۰ نویسه دارد.
- فهرست پروژه‌ها فقط متعلق به کاربر واردشده است.
- امکان تغییر نام، مشاهده گفتگوهای مرتبط و حذف پروژه وجود دارد.
- کاربر می‌تواند یک پروژه را برای گفتگوی جاری انتخاب کند؛ گفتگوهای جدید در همان پروژه ذخیره می‌شوند.
- گفتگوی موجود نیز با انتخاب پروژه به آن متصل می‌شود.
- حذف پروژه، گفتگوهای آن را حذف نمی‌کند؛ رابطه پروژه از گفتگوها برداشته می‌شود.
- حذف حساب، پروژه‌های متعلق به حساب را با قاعده حذف آبشاری پاک می‌کند.
- تمام APIها احراز هویت و کنترل مالکیت سمت سرور دارند؛ شناسه پروژه به‌تنهایی مجوز دسترسی نیست.

## API

- GET /api/projects: فهرست پروژه‌های کاربر.
- POST /api/projects: ایجاد پروژه.
- GET /api/projects/:id: اطلاعات پروژه و حداکثر ۵۰ گفتگوی اخیر آن.
- PUT /api/projects/:id: تغییر عنوان و توضیح.
- DELETE /api/projects/:id: حذف پروژه بدون حذف گفتگوها.

در API تاریخچه گفتگو، فیلد اختیاری project_id برای ایجاد یا اتصال گفتگو پشتیبانی می‌شود. مقدار باید متعلق به همان کاربر باشد؛ null گفتگو را از پروژه جدا می‌کند.

## فعال‌سازی محیط

Migration شماره 0012_user_projects.sql پس از migration شماره 0011_conversation_history.sql به D1 اضافه شده است. این migration فقط در شاخه کد ثبت شده و از اینجا روی دیتابیس واقعی اجرا نشده است.

پیش از اجرای migration روی محیط واقعی:
1. وضعیت migrationهای ثبت‌شده و pending بررسی شود.
2. از دیتابیس نسخه پشتیبان گرفته شود.
3. migrationهای pending به ترتیب و ابتدا در staging اجرا شوند.
4. تست مالکیت بین دو حساب مستقل انجام شود.

اجرای migration از طریق Wrangler ممکن است تمام migrationهای pending قبلی را نیز اجرا کند؛ فقط migration شماره ۰۰۱۲ را جداگانه فرض نکنید.

## محدودیت فعلی

بارگذاری فایل، فضای ذخیره‌سازی شیء، اشتراک‌گذاری پروژه، اعضای تیم، نقش‌های پروژه و نسخه‌بندی فایل‌ها هنوز پیاده‌سازی نشده‌اند. تا زمان اتصال و اجرای D1/Auth در محیط مستقر، قابلیت پروژه‌ها عملیاتی نیست.
