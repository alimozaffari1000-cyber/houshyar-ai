# سامانه عامل‌های توسعه آنلاین و آفلاین هوش‌یار

## تصمیم معماری

مقصد انتشار هوش‌یار **Cloudflare Pages** است. برای عامل‌های توسعه Worker مستقل ساخته نمی‌شود و این مرحله به D1 عملیاتی وابسته نیست.

دو محیط اجرایی داریم:
1. **عامل آنلاین:** در GitHub Actions اجرا می‌شود؛ پژوهش محدود، برنامه توسعه، آزمون، اسکن امنیتی و build را انجام می‌دهد و گزارش‌ها را به‌صورت Artifact نگه می‌دارد.
2. **عامل آفلاین:** با Node.js روی دستگاهی که مخزن و وابستگی‌ها روی آن نصب است اجرا می‌شود. بررسی‌های محلی به اینترنت یا API هوش مصنوعی نیاز ندارند.

## نقش‌ها

- معمار: بررسی معماری و سازگاری Pages
- پژوهشگر: گردآوری تغییرات از منابع عمومی مجاز
- برنامه‌ریز توسعه: تبدیل شواهد و وضعیت مخزن به کارهای اولویت‌بندی‌شده
- توسعه‌دهنده: آماده‌سازی تغییر در branch ایزوله؛ نیازمند بازبینی انسانی
- آزمون‌گر: اجرای تست‌های خودکار
- نگهبان امنیت: اسکن ایستا و بازبینی مرزهای امنیتی
- کیفیت و کارایی: کنترل build و حجم assetها
- نگهبان پروژه: تشخیص شکست‌ها و ثبت Issue
- مدیر انتشار: بررسی چک‌لیست؛ بدون اختیار انتشار

## عامل آنلاین

Workflow در مسیر `.github/workflows/online-development-agent.yml` هفتگی و با اجرای دستی طراحی شده است. پس از فعال شدن روی شاخه پیش‌فرض، این مراحل را اجرا می‌کند:

1. `npm run agent:research`: دریافت RSS رسمی Cloudflare و GitHub از فهرست ثابت میزبان‌های مجاز.
2. `npm run agent:plan`: خواندن آخرین گزارش پژوهش و تولید برنامه اولویت‌بندی‌شده در قالب JSON.
3. `npm run agent:offline`: اجرای audit، تست، اسکن امنیتی، build و کنترل کیفیت.
4. بارگذاری گزارش‌ها به‌عنوان Artifact؛ در صورت شکست، ایجاد Issue تشخیصی.

پژوهشگر حداکثر پنج آیتم از هر منبع را می‌خواند، لینک‌ها را به میزبان همان منبع محدود می‌کند و متن منبع را داده غیرقابل‌اعتماد می‌داند. این ابزار موتور جست‌وجوی عمومی وب نیست.

برنامه‌ریز توسعه به‌صورت پیش‌فرض برنامه قطعی و مبتنی بر شواهد می‌سازد. اگر درگاه مدل به‌صورت امن فعال شود، فقط یک بازبینی متنی از پیشنهادها دریافت می‌کند. خروجی مدل دستور اجرایی نیست و هیچ patch را اعمال نمی‌کند.

## عامل پیشنهاددهنده Patch

اسکریپت `scripts/agent-patch-proposal.mjs` مرحله آزمایشی تولید Patch را اضافه می‌کند. در صورت فعال بودن امن درگاه مدل، فقط دو فایل ثابت مربوط به اعتبارسنجی تصویر و تست آن‌ها به مدل داده می‌شود. خروجی باید unified diff باشد و فقط همین مسیرهای از پیش مجاز را تغییر دهد.

پیشنهاد حداکثر ۲۴ کیلوبایت و دو فایل است؛ ایجاد، حذف، تغییرنام، فایل باینری، مسیرهای دیگر و traversal رد می‌شوند. سپس فقط `git apply --check` اجرا می‌شود. Patch معتبر به‌عنوان Artifact ذخیره می‌شود؛ **هرگز خودکار اعمال نمی‌شود**. در حالت پیش‌فرض که مدل خاموش است، این مرحله بدون تولید Patch رد می‌شود. اعمال Patch، ساخت branch، اجرای CI روی تغییر پیشنهادی و ساخت PR در مرحله جداگانه و با کنترل انسانی انجام می‌شود.

فرمان:

```bash
npm run agent:patch
```

## اجرای آزمایشی Patch در محیط ایزوله

پس از تولید Patch پیشنهادی، `scripts/agent-patch-sandbox.mjs` آن را در یک Git worktree موقت و detached آزمایش می‌کند:

1. اعتبارسنجی مجدد مسیرها و اندازه Patch با همان allowlist سخت‌گیرانه
2. ساخت worktree موقت از همان commit فعلی
3. نصب وابستگی‌ها فقط در worktree با `npm install --ignore-scripts`؛ اسکریپت نصب بسته‌ها اجرا نمی‌شود
4. اجرای `git apply --check` و سپس اعمال Patch فقط داخل worktree موقت
5. اجرای فرمان‌های ثابت و غیرقابل‌تغییر: `npm run qa`، `npm run security:scan`، `npm run build` و `npm run quality:check`
6. حذف worktree و ذخیره گزارش JSON

فرمان دستی:

```bash
npm run agent:patch-sandbox -- --allow-local-execution
```

این مرحله هیچ‌گاه روی checkout اصلی Patch را اعمال نمی‌کند؛ commit، push، branch انتشار، PR، merge یا deploy نمی‌سازد. اجرای محلی به‌صورت پیش‌فرض مسدود است، چون کد تست‌شونده ممکن است با سطح دسترسی همان دستگاه اجرا شود؛ فقط با گزینه صریح بالا فعال می‌شود. در GitHub Actions، اجرا روی runner موقت انجام می‌شود. Git worktree جداسازی فایل‌های کاری است، نه sandbox امنیتی سطح سیستم‌عامل؛ بنابراین این مکانیزم مجوز اجرای Patch ناشناس روی دستگاه شخصی نیست. اگر Patch وجود نداشته باشد (مثلاً چون مدل خاموش است)، مرحله با وضعیت skipped تمام می‌شود. اگر هر بررسی شکست بخورد، نتیجه ناموفق ثبت می‌شود و workflow به‌عنوان موفق گزارش نمی‌شود.

## عامل آفلاین

فرمان بررسی:

```bash
npm run agent:offline
```

گزارش در `.houshyar-agent-reports/` ذخیره می‌شود. تعمیرات محدود و allowlist‌شده فقط با درخواست صریح:

```bash
npm run agent:offline -- --safe-repair
```

این گزینه اجازه بازنویسی کد برنامه، دسترسی به secret یا انتشار نمی‌دهد.

## درگاه مدل هوش مصنوعی

ماژول `scripts/agent-model-provider.mjs` به‌صورت پیش‌فرض خاموش است. تنظیمات فقط در محیط امن runner تعریف می‌شوند:
- `HOUSHYAR_AGENT_MODEL_MODE=online` با URL از نوع HTTPS و کلید سمت سرور
- `HOUSHYAR_AGENT_MODEL_MODE=offline` فقط با loopback مانند `http://127.0.0.1:11434/v1`
- `HOUSHYAR_AGENT_MODEL_NAME` برای نام مدل
- `HOUSHYAR_AGENT_MODEL_API_KEY` فقط برای سرویس آنلاین

درگاه مدل فقط وظایف allowlist‌شده را می‌پذیرد؛ shell، دسترسی فایل، نوشتن کد، merge و deploy ندارد. تا زمان پیکربندی آگاهانه، هیچ هزینه یا اتصال مدل ایجاد نمی‌شود.

## عامل پیش‌بررسی انتشار

عامل مدیر انتشار در `scripts/agent-release-preflight.mjs` یک گزارش پیش‌بررسی می‌سازد. این گزارش موارد زیر را بررسی می‌کند:
- اجرای کار روی شاخه‌ای غیر از `main` و تمیز بودن وضعیت Git
- شناسایی commit دقیق
- وجود سیاست Pages و ممنوعیت تغییر مستقیم main و تولید
- وجود گزارش موفق اجرای sandbox برای هر چهار بررسی
- وجود گزارش آفلاین با پنج بررسی موفق

فرمان:

```bash
npm run agent:release-check
```

نتیجه موفق فقط به معنی «آماده برای بازبینی انسانی» است؛ مجوز انتشار نیست. CI روی همان commit، بازبینی PR، آزمون preview در Pages و بررسی secrets و migrationها همچنان باید توسط انسان تأیید شوند. نبود گزارش sandbox یا شکست هر بررسی، وضعیت را مسدود می‌کند. این عامل هیچ merge یا deploy انجام نمی‌دهد و حتی در حالت موفق نیز `productionReleaseAuthorized` همیشه `false` باقی می‌ماند.

## محدودیت آفلاین روی موبایل

اجرای محلی به Node.js، Git، مخزن و وابستگی‌های نصب‌شده نیاز دارد. اجرای دائمی در پس‌زمینه اندروید تضمین‌شده نیست؛ بنابراین این نسخه را عامل همیشه‌روشن گوشی نمی‌نامیم.

## مرز خودمختاری و ایمنی

عامل‌ها اکنون تحقیق محدود، برنامه‌ریزی، بررسی و گزارش را خودکار می‌کنند؛ هنوز کد برنامه را خودکار تغییر نمی‌دهند. مرحله بعدی توسعه‌دهنده می‌تواند patch پیشنهادی را در محیط ایزوله بسازد، اما فقط پس از اعتبارسنجی مسیر فایل‌ها، بررسی patch، اجرای تست و بازبینی امنیتی باید PR ایجاد شود.

هیچ عامل اجازه shell آزاد، دسترسی به کلیدها یا داده خصوصی، تغییر پرداخت، تغییر مجوزها، merge به main یا انتشار Pages را ندارد. ادغام، migration تولیدی و انتشار نیازمند تأیید انسانی مستقل هستند.

## وضعیت

این تغییرات زیرساخت برنامه‌ریزی توسعه را به PR اضافه می‌کنند. تا پیش از ادغام PR در شاخه پیش‌فرض، workflow زمان‌بندی‌شده روی مخزن فعال نمی‌شود. ایجاد گزارش در branch نیز به معنی فعال بودن عامل در سایت عمومی نیست.
