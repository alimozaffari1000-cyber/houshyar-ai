# سامانه عامل‌های توسعه آنلاین و آفلاین هوش‌یار

## تصمیم معماری

مقصد انتشار هوش‌یار **Cloudflare Pages** باقی می‌ماند. این سامانه برای اجرای عامل‌های توسعه، Worker مستقل Cloudflare نمی‌سازد و به D1 عملیاتی وابسته نیست.

دو محیط اجرایی جدا داریم:

1. **عامل آنلاین:** در GitHub Actions اجرا می‌شود؛ مخزن را بررسی می‌کند، آزمون و build می‌گیرد، گزارش تولید می‌کند و در صورت شکست یک Issue تشخیصی باز می‌کند.
2. **عامل آفلاین:** با Node.js روی رایانه‌ای که مخزن و وابستگی‌های آن روی آن موجود است اجرا می‌شود. برای اجرای بررسی‌های محلی به اینترنت یا API هوش مصنوعی نیاز ندارد.

## نقش‌ها

- معمار: بررسی سازگاری معماری با Pages و ثبت پیشنهاد
- توسعه‌دهنده: آماده‌سازی تغییرات در branch و PR؛ ادغام فقط با تأیید انسانی
- آزمون‌گر: اجرای تست‌های خودکار
- نگهبان امنیت: اسکن ایستای الگوهای شناخته‌شده کلید و رمز
- کیفیت و کارایی: بررسی build و سقف حجم assetها
- نگهبان پروژه: تشخیص شکست‌ها و ساخت گزارش/Issue
- پژوهشگر: آماده‌سازی موضوعات تحقیق؛ پژوهش وب به اتصال منبع معتبر نیاز دارد
- مدیر انتشار: بررسی چک‌لیست انتشار؛ بدون اختیار انتشار

## عامل آنلاین

Workflow در مسیر `.github/workflows/online-development-agent.yml` به‌صورت هفتگی و با اجرای دستی فعال می‌شود.

دسترسی‌ها:
- خواندن محتویات مخزن
- اجرای تست، اسکن امنیتی و build
- بارگذاری گزارش به‌عنوان Artifact
- ساخت Issue تشخیصی در صورت شکست

ممنوع:
- تغییر فایل‌های برنامه
- push یا merge
- انتشار Pages
- اجرای migration عملیاتی
- خواندن secrets یا داده خصوصی کاربران

این عامل «آنلاین» است چون روی زیرساخت GitHub اجرا می‌شود؛ در نسخه فعلی، عامل پژوهشگر به موتور جست‌وجوی وب یا مدل زبانی مستقل متصل نیست و نباید ادعای تحقیق خودکار اینترنتی داشته باشیم.

## عامل آفلاین

فرمان اصلی:

```bash
npm run agent:offline
```

این فرمان به‌ترتیب بررسی ساختار Pages، تست‌ها، اسکن امنیتی، build و کنترل کیفیت را اجرا و گزارش را در `.houshyar-agent-reports/` ذخیره می‌کند.

تعمیرات محدود و allowlist‌شده فقط با درخواست صریح:

```bash
npm run agent:offline -- --safe-repair
```

در حال حاضر تعمیر خودکار فقط از اسکریپت موجود `agent:repair` استفاده می‌کند که قواعد امن ignore و تنظیم Pages را بررسی می‌کند. این گزینه به عامل اجازه بازنویسی کد برنامه، دسترسی به secret یا انتشار نمی‌دهد.

## آفلاین واقعی روی موبایل

اجرای محلی Node.js به محیطی نیاز دارد که Node.js، Git، مخزن و وابستگی‌های نصب‌شده را داشته باشد. اجرای پایدار در پس‌زمینه اندروید تضمین‌شده نیست. بنابراین این نسخه را نمی‌توان «عامل همیشه‌روشن روی گوشی» نامید. برای اجرای آفلاین دائمی باید بعداً یک رایانه/سرور محلی یا دستگاه همیشه‌روشن با runner مدیریت‌شده فراهم شود.

## مرز خودمختاری و ارتقای مرحله‌ای

نسخه فعلی عامل‌ها بررسی و گزارش را خودکار می‌کنند؛ تغییر کد، ایجاد PR توسط مدل، پژوهش وب، اجرای مدل محلی و تعمیر کد هنوز پیاده‌سازی نشده‌اند.

برای مرحله بعد، مسیر امن چنین است:
1. عامل پژوهش فقط منابع عمومی را بخواند و گزارش همراه پیوند/تاریخ بسازد.
2. عامل توسعه پیشنهاد را در branch ایزوله بسازد؛ هر patch باید تست شود.
3. عامل QA و امنیت مستقل از عامل توسعه، تغییر را بررسی کنند.
4. PR ساخته شود؛ merge به main فقط با تأیید انسانی.
5. انتشار Pages و migration تولیدی همیشه مرحله جداگانه و نیازمند تأیید بماند.

هیچ عامل نباید shell آزاد، کلیدها، داده خصوصی کاربران، پرداخت، تغییر مجوزها یا اختیار انتشار مستقیم داشته باشد.

## وضعیت این نسخه

این PR فقط زیرساخت اولیه آنلاین/آفلاین، نقش‌ها، گزارش و مرزهای مجوز را اضافه می‌کند. تا زمانی که PR بررسی و ادغام نشده و workflow در شاخه پیش‌فرض فعال نشده باشد، عامل آنلاین زمان‌بندی‌شده فعال محسوب نمی‌شود. اجرای عامل آفلاین نیز نیازمند دریافت مخزن و اجرای فرمان روی دستگاه دارای Node.js است.
