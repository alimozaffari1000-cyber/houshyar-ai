# زیرساخت امن تصاویر بازار هوش‌یار

## وضعیت
این مرحله مسیر بارگذاری امن و ذخیره‌سازی خصوصی تصاویر را اضافه می‌کند. فایل‌ها در R2 ذخیره می‌شوند، اما هنوز به صفحه عمومی محصول متصل نیستند و URL عمومی برایشان صادر نمی‌شود. تا زمان ساخت مسیر نمایش کنترل‌شده و اتصال شناسه تصویر به محصول، این endpoint را قابلیت داخلی/آزمایشی در نظر بگیرید.

## پیش‌نیاز Cloudflare
1. در Cloudflare داشبورد، یک R2 bucket بسازید (برای نمونه: `houshyar-market-media`).
2. در تنظیمات Pages پروژه، بخش Settings → Bindings، یک R2 bucket binding اضافه کنید.
3. نام متغیر binding را دقیقاً `R2_BUCKET` بگذارید و bucket ساخته‌شده را انتخاب کنید.
4. متغیرهای محرمانه یا کلید عمومی لازم نیست؛ این binding به‌صورت مستقیم از runtime استفاده می‌شود.
5. تا وقتی binding تنظیم نشده، API پاسخ `503 IMAGE_STORAGE_NOT_CONFIGURED` می‌دهد.

## API
- روش: `POST /api/market/images/upload`
- احراز هویت: session کاربر الزامی است.
- نوع بدنه: `multipart/form-data`
- فیلدها: `image` (فایل)، `storeId`، `country` (یکی از IR/AE/DE/TR)
- سقف حجم: ۵ مگابایت
- فرمت‌ها: JPEG، PNG، WebP
- مالکیت: فروشگاه باید متعلق به کاربر واردشده و در همان کشور باشد؛ فروشگاه pending یا active مجاز است.
- محدودیت نرخ: حداکثر ۱۵ بار در ساعت برای هر کاربر.
- نام فایل اصلی هرگز برای ساخت کلید ذخیره‌سازی استفاده نمی‌شود؛ کلید تصادفی ساخته می‌شود.
- MIME اعلامی با امضای باینری فایل تطبیق داده می‌شود.
- پاسخ شامل `imageId` است؛ object key در پایگاه داده خصوصی می‌ماند و هرگز به مرورگر داده نمی‌شود. پس از اجرای migration شماره 0011 می‌توان imageId را هنگام ساخت آگهی در آرایه `imageIds` فرستاد.

## امنیت و کارهای باقی‌مانده
- این مسیر به‌تنهایی تصویر را به listing متصل نمی‌کند.
- مرحله بعد: جدول/رابط اتصال image asset به listing، نمایش از طریق Worker/Pages Function کنترل‌شده با بررسی وضعیت انتشار، حذف امن تصاویر و پاکسازی فایل‌های orphan.
- برای production باید تست integration با R2 واقعی و بررسی CORS/origin/session انجام شود.
- از قراردادن R2 bucket به‌صورت public و از URL عمومی بدون کنترل دسترسی خودداری کنید.
