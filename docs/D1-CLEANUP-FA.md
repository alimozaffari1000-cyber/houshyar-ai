# پاک‌سازی زمان‌بندی‌شده داده‌های امنیتی

Workflow فایل .github/workflows/d1-security-cleanup.yml هر دوشنبه ساعت 04:17 UTC و در صورت اجرای دستی، پاک‌سازی را روی D1 راه دور انجام می‌دهد.

## پیش‌نیازها

در GitHub repository secrets این سه مقدار را تنظیم کنید:

- CLOUDFLARE_API_TOKEN: توکن Cloudflare با حداقل دسترسی لازم برای اجرای D1 روی پایگاه هدف.
- CLOUDFLARE_ACCOUNT_ID: شناسه حساب Cloudflare.
- CLOUDFLARE_D1_DATABASE_NAME: نام دقیق پایگاه D1 هدف.

اگر هر کدام از این سه secret تنظیم نشده باشد، workflow به‌صورت امن از پاک‌سازی صرف‌نظر می‌کند. نام پایگاه دیگر در کد workflow hard-code نشده است؛ بنابراین باید مقصد به‌صورت صریح توسط مدیر مخزن تعیین شود.

## داده‌هایی که حذف می‌شوند

- توکن‌های تأیید ایمیل منقضی یا مصرف‌شده.
- توکن‌های بازیابی رمز منقضی یا مصرف‌شده.
- نشست‌های منقضی یا باطل‌شده.
- bucketهای محدودیت نرخ منقضی‌شده.

رویدادهای ممیزی و سوابق مصرف مدل عمداً حذف نمی‌شوند؛ نگهداری آن‌ها باید طبق سیاست حریم خصوصی، نیازهای عملیاتی و الزامات قانونی جداگانه تعیین شود.

## کنترل ایمنی

- نبود هر یک از سه secret باعث skip امن می‌شود؛ workflow به‌طور خودکار نام پایگاه را حدس نمی‌زند.
- فایل SQL فقط شامل DELETEهای محدود به رکوردهای منقضی/مصرف‌شده است.
- پیش از تنظیم secrets، نام D1 و سطح دسترسی توکن را بررسی و از پایگاه هدف نسخه پشتیبان تهیه کنید.
- برای staging و production از پایگاه‌ها و secrets جداگانه استفاده کنید.
- پس از اولین اجرای دستی، گزارش موفقیت GitHub Actions و تعداد ردیف‌های تغییرکرده را بررسی کنید.
