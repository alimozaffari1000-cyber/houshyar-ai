# چک‌لیست آماده‌سازی بازار هوش‌یار برای انتشار

این سند وضعیت فعلی بازار کشورمحور را از «کد موجود در شاخه توسعه» تا «فعال‌سازی امن در محیط واقعی» تفکیک می‌کند. وجود کد یا سبز بودن CI به معنی فعال بودن قابلیت در سایت عمومی نیست.

## وضعیت قابلیت‌ها در شاخه توسعه

- انتخاب بازار کشور و جداسازی داده‌ها: پیاده‌سازی اولیه برای IR، AE، DE و TR.
- ساخت فروشگاه و ثبت آگهی: API و پنل فروشنده؛ هر دو نیازمند ورود کاربر و بررسی مدیر هستند.
- صف بررسی مدیر: API و پنل محدود به نقش admin.
- بارگذاری تصویر: بررسی MIME و امضای باینری JPEG/PNG/WebP، سقف ۵ مگابایت، حداکثر ۶ تصویر برای هر آگهی، ذخیره فایل در R2 و metadata در D1.
- پاک‌سازی تصویرهای بارگذاری‌شده ولی استفاده‌نشده: endpoint حذف فقط برای مالک؛ تصویر متصل به آگهی قابل حذف از این مسیر نیست.
- نمایش عمومی: API فروشگاه فعال، آگهی منتشرشده، جزئیات آگهی و تصویر؛ صفحه مستقل و کامل SEO/UX برای هر محصول و فروشگاه هنوز مرحله بعد است.

## پیش‌نیازهای Cloudflare

1. در Cloudflare Pages برای Production و Preview، binding دیتابیس D1 با نام دقیق `DB` متصل شود.
2. binding فضای ذخیره‌سازی R2 با نام دقیق `R2_BUCKET` متصل شود.
3. ابتدا migrations را روی دیتابیس آزمایشی اجرا و بررسی کنید؛ سپس روی دیتابیس Production:
   - `0001_identity_usage_security.sql`
   - `0010_country_marketplace.sql`
   - `0011_marketplace_images.sql`
4. قبل از اجرای migrationها، از دیتابیس Production نسخه پشتیبان بگیرید.
5. فایل‌های R2 باید private بمانند؛ دسترسی عمومی مستقیم به bucket فعال نشود. فایل‌ها فقط از endpoint کنترل‌شده هوش‌یار سرو شوند.

## تست پذیرش قبل از انتشار

- کاربر واردنشده نتواند فروشگاه، آگهی یا تصویر ثبت کند.
- کاربر A نتواند فروشگاه یا تصویر کاربر B را دستکاری کند.
- بازار IR هیچ داده‌ای از AE/DE/TR برنگرداند و برعکس.
- فروشگاه pending و آگهی pending در API عمومی دیده نشوند.
- مدیر غیرادمین نتواند صف بررسی یا عملیات تأیید/رد را اجرا کند.
- آگهی بدون فروشگاه فعال قابل انتشار نباشد.
- فایل با پسوند جعلی، MIME غیرمجاز، امضای باینری نامعتبر یا حجم بیش از ۵MB رد شود.
- کاربر نتواند بیش از ۶ تصویر به یک آگهی متصل کند یا تصویر متعلق به فروشگاه دیگر را استفاده کند.
- در صورت شکست ثبت آگهی، رکورد ناقص یا رابطه تصویر یتیم در D1 ایجاد نشود؛ درج آگهی و روابط تصویر در یک D1 batch انجام می‌شود.
- پاک‌سازی تصویر استفاده‌نشده فقط برای مالک انجام شود و تصویر متصل به آگهی حذف نشود.
- رفتار حذف و بازیابی فایل در صورت خطای موقت R2 بررسی شود.

## محدودیت‌ها و کارهای باز

- کشورهای فعال فعلاً فقط IR/AE/DE/TR هستند؛ انتخاب کشور به معنی پشتیبانی حقوقی، پرداختی یا عملیاتی کامل در آن کشور نیست.
- قیمت فعلی به صورت عدد صحیح ذخیره می‌شود؛ واحدهای اعشاری ارزهایی مانند EUR/AED/TRY هنوز به مدل minor-unit تبدیل نشده‌اند. پیش از فروش واقعی باید مدل مبلغ و نمایش ریال/تومان/ارز محلی اصلاح و تست شود.
- پرداخت، سبد خرید، سفارش، موجودی، ارسال، مالیات، بازپرداخت، اختلاف معامله و تسویه فروشنده هنوز برای استفاده واقعی آماده نیستند.
- احراز هویت فروشنده، ضدتقلب پیشرفته، پیام‌رسانی خریدار/فروشنده، گزارش آگهی و مدیریت شکایت باید پیش از باز کردن بازار عمومی تکمیل شوند.
- پرو مجازی پوشاک و اندازه‌گیری سه‌بعدی واقعی هنوز ساخته نشده‌اند؛ مرحله اول مناسب، try-on تصویری با رضایت و کنترل حریم خصوصی است.
- هیچ داده، تصویر، آگهی یا نظر کاربران دیوار و شیپور نباید بدون مجوز کپی یا scrape شود.

## ترتیب پیشنهادی ادامه توسعه

1. تکمیل صفحات واقعی جزئیات محصول و فروشگاه، همراه با لینک‌پذیری و metadata مناسب موتور جست‌وجو.
2. علاقه‌مندی‌ها و ذخیره آگهی‌ها.
3. پیام امن خریدار و فروشنده و گزارش/مسدودسازی.
4. پنل سفارش و موجودی؛ ابتدا بدون پرداخت آنلاین.
5. اصلاح مدل قیمت به واحد خرد ارز و تست چندارزی.
6. سبد خرید و checkout آزمایشی؛ سپس بررسی حقوقی و پرداخت واقعی بر اساس کشور ثبت و فعالیت شرکت.
7. بهبود عملکرد، دسترس‌پذیری، ضداسپم، پایش خطا و پشتیبان‌گیری.

## وضعیت انتشار

این تغییرات در شاخه توسعه و PR مربوطه نگهداری می‌شوند. تا وقتی تست CI، بررسی D1/R2 آزمایشی و تأیید نهایی انجام نشده، PR نباید merge و قابلیت‌ها نباید در Production فعال شوند.
