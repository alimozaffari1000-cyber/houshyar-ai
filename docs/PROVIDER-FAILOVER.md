# راهنمای failover ارائه‌دهندگان هوش‌یار

## رفتار

- در حالت انتخاب خودکار (provider: auto)، اگر ارائه‌دهنده منتخب به علت خطای شبکه، timeout یا پاسخ HTTP موقت (408، 425، 429 یا 5xx) شکست بخورد، API یک بار ارائه‌دهنده دیگرِ پیکربندی‌شده را امتحان می‌کند.
- خطاهای عادی 4xx مانند 400 و 401 باعث failover نمی‌شوند؛ این خطاها معمولاً به درخواست یا اعتبارنامه مربوط‌اند.
- انتخاب صریح groq یا anthropic به انتخاب کاربر احترام می‌گذارد و بی‌صدا به سرویس دیگری جابه‌جا نمی‌شود.
- مقایسه دو مدل مسیر مستقل دارد و failover خودکار در آن اجرا نمی‌شود؛ تعداد فراخوانی‌ها و هزینه مقایسه ناخواسته افزایش نمی‌یابد.
- پاسخ موفق پس از failover فیلد fallback شامل from و reason را برمی‌گرداند.

## هزینه و سهمیه

- failover حداکثر یک فراخوانی اضافه به ارائه‌دهنده دوم ایجاد می‌کند.
- سهمیه کاربر برای یک پیام عادی فقط یک بار رزرو می‌شود؛ fallback رزرو دوم سهمیه ایجاد نمی‌کند.
- مصرف واقعی provider دوم ممکن است جداگانه هزینه داشته باشد. ثبت هزینه و توکن هر provider و هشدار بودجه باید در لایه گزارش‌دهی تکمیل شود.
- خطاهای مبهم پس از ارسال درخواست ممکن است در provider اول نیز هزینه ایجاد کرده باشند؛ failover تضمین نمی‌کند درخواست اول بدون هزینه بوده است.

## پیکربندی

برای failover دوطرفه، هر دو secret سروری GROQ_API_KEY و CLAUDE_API_KEY باید در محیط Cloudflare Pages تنظیم شوند. مدل‌ها از GROQ_MODEL و متغیرهای مدل Groq و CLAUDE_MODEL انتخاب می‌شوند. هیچ secret در کد یا پاسخ API قرار نمی‌گیرد.

## محدودیت اعتبارسنجی

تست‌های خودکار رفتار انتخاب provider، خطاهای موقت و 4xx را پوشش می‌دهند. این تغییر به‌تنهایی اتصال secretها، اعتبار حساب‌ها، دسترسی منطقه‌ای یا سلامت زنده APIها را در Cloudflare آزمایش نمی‌کند.
