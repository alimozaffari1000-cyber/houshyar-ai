# پایه قابلیت تست مجازی محصول در هوش‌یار

## هدف محصول

قابلیت «تست مجازی» به خریدار اجازه می‌دهد عکس فضای واقعی یا عکس خودش را بارگذاری کند، یک محصول فروشگاهی را انتخاب کند و پیش‌نمایش واقع‌گرایانه بگیرد. فروشنده می‌تواند این قابلیت را برای هر محصول واجد شرایط فعال کند.

این قابلیت باید در بازارگاه و صفحه محصول قابل دسترسی باشد؛ نه صرفاً یک ابزار جدا از فروشگاه.

## تجربه خریدار

1. انتخاب نوع تجربه:
   - چیدمان خانه: مبل، میز، صندلی، فرش، پرده، چراغ و دکور.
   - پرو لباس: پوشاک روی تصویر تمام‌قد کاربر.
2. بارگذاری عکس محیط یا تصویر شخصی؛ راهنمای کیفیت و زاویه مناسب نمایش داده شود.
3. انتخاب محصول از بازارگاه یا فروشگاه.
4. تولید پیش‌نمایش با هوش مصنوعی، مشاهده نسخه اصلی و نتیجه، مقایسه و ذخیره/حذف خروجی.
5. لینک بازگشت به همان محصول و فروشگاه برای خرید.

## تجربه فروشنده

- افزودن چند تصویر محصول با زاویه‌های مختلف.
- تعیین دسته بصری دقیق (پوشاک، مبلمان، دکور، روشنایی، الکترونیک، سایر).
- روشن/خاموش کردن تست مجازی برای هر محصول.
- راهنمای عکس مناسب و نمایش وضعیت آماده‌بودن محصول برای تست.
- عدم نمایش دکمه تست برای محصول فاقد تصویر معتبر یا محصول غیرفعال.

## معماری فنی پیشنهادی

### داده و فایل
- D1 فقط فراداده را نگه می‌دارد؛ فایل تصویر داخل D1 ذخیره نمی‌شود.
- تصاویر محصولات فروشندگان در Cloudflare R2 نگهداری می‌شوند؛ کلید شیء در جدول product_media ثبت می‌شود.
- عکس اتاق/بدن خریدار به‌صورت پیش‌فرض موقت است؛ بدون رضایت صریح ذخیره دائمی نشود.
- خروجی تولیدشده نیز پیش‌فرض موقت باشد و کاربر بتواند آن را حذف کند.
- تصاویر خصوصی کاربر نباید در URL عمومی، log، analytics یا پاسخ خطا افشا شوند.

### پردازش هوش مصنوعی
- یک لایه provider adapter سمت سرور طراحی شود؛ کلید سرویس تصویر هرگز به مرورگر نرود.
- دو pipeline مجزا لازم است:
  1. Virtual staging / object placement برای مبلمان و اشیای خانه؛ حفظ هندسه، پرسپکتیو، نور و سایه محیط.
  2. Virtual try-on برای پوشاک؛ حفظ هویت و ژست کاربر و نمایش صحیح اندازه/فرم لباس.
- در صورت امکان، ماسک/ناحیه هدف، عمق و تشخیص سطح برای جای‌گذاری دقیق‌تر استفاده شود.
- خروجی باید به‌عنوان «پیش‌نمایش تقریبی» معرفی شود، نه تضمین رنگ، اندازه یا تناسب واقعی.
- پردازش باید دارای سقف اندازه/ابعاد فایل، محدودیت نرخ، timeout، هزینه‌سنجی و صف باشد.

### حریم خصوصی و امنیت
- اعتبارسنجی MIME واقعی و امضای فایل؛ فقط JPEG/PNG/WebP.
- محدودیت حجم و ابعاد؛ حذف metadata حساس مانند EXIF و مختصات GPS.
- نام فایل کاربر به‌عنوان object key استفاده نشود؛ کلید تصادفی سمت سرور.
- R2 private bucket برای عکس‌های کاربر و خروجی‌ها؛ لینک‌های امضاشده کوتاه‌عمر.
- حذف خودکار فایل‌های موقت و مسیر حذف دستی فوری.
- مجوز صریح برای ارسال تصویر به provider پردازش تصویر و توضیح محل/مدت نگهداری.
- کنترل مالکیت محصول و session در تمام endpointها؛ audit رویدادهای مدیریتی بدون ثبت محتوای تصویر.

## مرحله‌بندی انتشار

### مرحله A — پایه داده (این PR)
- دسته بصری و پرچم فعال‌سازی تست مجازی برای محصول.
- جدول چندتصویری محصول.
- بدون تغییر دیتابیس راه‌دور و بدون فعال‌سازی UI عمومی.

### مرحله B — مدیریت تصاویر فروشنده
- R2 binding و آپلود امن، حذف و مرتب‌سازی تصاویر.
- نمایش تصویر واقعی محصول در کاتالوگ.
- تست محدودیت‌های فایل و مجوز فروشنده.

### مرحله C — تجربه خریدار
- انتخاب عکس خانه/بدن و محصول.
- preview محلی قبل از ارسال.
- رضایت آگاهانه، پردازش سمت سرور و نمایش نتیجه.

### مرحله D — اتصال مدل و انتشار کنترل‌شده
- ارزیابی providerها روی مجموعه عکس‌های نمونه با رضایت و مجوز.
- مقایسه کیفیت، زمان پاسخ، هزینه هر تصویر، محدودیت کشورها و سیاست نگهداری.
- ابتدا staging و گروه آزمایشی؛ سپس rollout تدریجی.

## معیارهای پذیرش

- عکس شخصی کاربر بدون رضایت در هیچ storage دائمی ذخیره نشود.
- تصاویر محصول فقط توسط مالک فروشگاه فعال مدیریت شوند.
- محصول بدون عکس معتبر قابلیت تست مجازی نداشته باشد.
- تست خانه و پرو لباس pipelineهای مستقل داشته باشند.
- خطاهای provider، کلیدها و URLهای خصوصی در پاسخ API/log افشا نشوند.
- کاربر بتواند تصویر ورودی و خروجی موقت را حذف کند.
- UI هرگز پیش‌نمایش ساختگی را به‌عنوان خروجی AI واقعی نشان ندهد.

## وضعیت فعلی

این تغییر فقط پایه داده و مشخصات فنی را آماده می‌کند. هنوز R2، سرویس تولید تصویر، endpoint پردازش، بارگذاری تصاویر و تولید پیش‌نمایش واقعی به پروژه متصل نشده‌اند. تا زمان پیاده‌سازی و آزمون مراحل B تا D، نباید این قابلیت در بازارگاه به‌عنوان فعال معرفی شود.
