# موتور خودتوسعه هوش‌یار — مشخصات اجرایی

نسخه: 1.0  
تاریخ: 2026-11-18  
وضعیت: سیاست و هسته کنترل اولیه در شاخه توسعه؛ موتور اجرایی کامل هنوز فعال نیست.

## هدف محصول

هوش‌یار باید بتواند با دریافت هدف‌های مجاز، وضعیت خودش را بررسی کند، کمبودها را تشخیص دهد، طرح توسعه بسازد، کار را به وظایف کوچک تقسیم کند، تغییرات را در محیط جداگانه پیاده‌سازی کند، آزمون بگیرد، خطاهای قابل‌رفع را اصلاح کند و نسخه آماده بازبینی بسازد. هدف نهایی کاهش دخالت روزمره مالک است؛ نه حذف کنترل مالک بر دارایی، داده، امنیت و انتشار عمومی.

## تعریف «بدون دخالت»

### خودکار و بدون تأیید برای هر بار
- پایش سلامت سرویس و کیفیت کد
- بررسی مستندات و منابع عمومی مجاز
- کشف باگ و پیشنهاد اولویت‌بندی‌شده
- نوشتن طرح، معیار پذیرش و برنامه تست
- ایجاد branch کاری مستقل
- تغییر کد در sandbox/branch مجاز
- اجرای تست، lint، build و اسکن امنیتی
- اصلاح خطاهای داخل محدوده همان task و اجرای مجدد تست
- ساخت گزارش و Pull Request
- بازگشت تغییرات branch آزمایشی در صورت شکست تست

### نیازمند تأیید انسانی
- ادغام در main
- انتشار production و تغییر دامنه/تنظیمات زیرساخت
- اجرای migration روی داده واقعی و هر عملیات برگشت‌ناپذیر
- تغییر دسترسی، سیاست امنیتی یا مدیریت secret
- مشاهده/خروجی‌گرفتن از داده خصوصی کاربران
- حذف داده، ارسال پیام بیرونی، انتشار عمومی
- پرداخت، انتقال دارایی، قرارداد یا تعهد حقوقی

### ممنوع
- shell نامحدود و اجرای فرمان دلخواه بدون sandbox
- خاموش‌کردن تست یا اسکن امنیتی برای سبز نشان‌دادن CI
- پاک‌کردن یا دستکاری سابقه ممیزی
- استخراج secretها یا قراردادن آن‌ها در prompt/log
- تغییر مستقیم production یا main توسط عامل خودمختار

## چرخه توسعه خودکار

1. **Observe:** جمع‌آوری وضعیت build، خطاها، dependencyها، تجربه کاربر و نیازهای محصول از منابع مجاز.
2. **Diagnose:** تبدیل شواهد به یافته؛ هر یافته باید منبع، زمان، شدت، اطمینان و دامنه اثر داشته باشد.
3. **Plan:** ساخت طرح فنی شامل مسئله، هدف، خارج از دامنه، وابستگی‌ها، معیار پذیرش، ریسک، تست و rollback.
4. **Prioritize:** امتیازدهی بر اساس اثر کاربر، شدت امنیتی، هزینه، زمان، وابستگی و اطمینان.
5. **Execute:** تخصیص به عامل تخصصی و ایجاد branch ایزوله؛ فقط ابزارهای allowlist شده.
6. **Verify:** تست واحد/یکپارچه، تست رگرسیون، build، دسترس‌پذیری، امنیت، هزینه و بررسی مجوزها.
7. **Repair:** حداکثر تعداد تلاش محدود؛ هر اصلاح باید قابل ردیابی باشد. پس از تکرار شکست، توقف و گزارش.
8. **Review:** تولید PR با خلاصه تغییرات، شواهد تست، ریسک، تصاویر preview در صورت نیاز و روش بازگشت.
9. **Release:** فقط پس از تأیید مجاز انسانی؛ انتشار مرحله‌ای و پایش سلامت.
10. **Learn:** ثبت نتیجه، علت شکست و معیار کیفیت برای بهبود برنامه‌های بعدی.

## معماری اجرایی موردنیاز

- **Self-Development Orchestrator:** مدیریت برنامه، اولویت و وابستگی taskها.
- **Planner:** تبدیل هدف محصول به issue/task با معیار پذیرش روشن.
- **Repository Worker:** کار روی branch محدود و sandbox؛ بدون دسترسی مستقیم به main.
- **Research Worker:** تحقیق منابع عمومی با ثبت URL و تاریخ؛ محتوای بازیابی‌شده غیرقابل‌اعتماد است.
- **QA Worker:** اجرای تست و جلوگیری از پذیرش نتیجه بدون شواهد.
- **Security Worker:** بررسی secret، dependency، auth، tenant isolation و مجوز ابزار.
- **Release Gate:** الزام تأیید انسانی برای merge، migration و production.
- **Audit Ledger:** ثبت append-only برای هر تصمیم، فراخوانی ابزار، تغییر فایل و نتیجه.
- **Runtime Adapter:** اتصال کنترل‌شده به GitHub، CI، مدل‌ها و در آینده محیط محلی.

## کنترل‌های فنی اجباری

- deny-by-default برای تمام actionها و ابزارهای ناشناخته.
- جداسازی tenant و مالکیت task.
- lease اتمیک، idempotency، timeout، retry محدود و dead-letter handling.
- سقف هزینه، token، زمان اجرا، حجم تغییرات و تعداد فایل.
- sandbox بدون secretهای production.
- اعتبارسنجی خروجی مدل به‌عنوان داده غیرقابل‌اعتماد؛ جلوگیری از prompt injection.
- محافظت از branch، امضای artifact و ثبت checksum برای buildهای مهم.
- backup، rollback و مراقبت از schema قبل از migration.
- kill switch برای توقف فوری همه اجراهای خودکار.
- پنل مشاهده‌پذیری: عامل، task، وضعیت، آخرین اجرا، زمان، هزینه، خطا و شواهد.

## سطوح خودمختاری

- **L0 — دستی:** فقط پیشنهاد.
- **L1 — برنامه‌ریز:** تحقیق و طرح را خودکار تولید می‌کند.
- **L2 — توسعه‌گر sandbox:** در branch ایزوله کد می‌نویسد و تست می‌کند.
- **L3 — آماده‌ساز انتشار:** PR و preview کامل می‌سازد؛ انسان merge/deploy می‌کند.
- **L4 — انتشار محدود خودکار:** فقط برای تغییرات کم‌خطر و برگشت‌پذیر با سیاست از پیش مصوب، پس از چندین دوره موفق و ارزیابی امنیتی مستقل. این سطح در نسخه فعلی مجاز/فعال نیست.

## وضعیت پیاده‌سازی در مخزن

- موجود: registry نقش‌ها، policy پایه عامل‌ها، API احراز هویت‌شده صف وظایف، schema چرخه عمر، رویداد اولیه ایجاد task، CI و آزمون‌های امنیت/کیفیت.
- اضافه‌شده در این تغییر: تابع سیاست خودتوسعه با allowlist، deny-by-default، ممنوعیت shell آزاد، قفل نوشتن production و الزام تأیید برای عملیات حساس؛ همراه با تست.
- موجود اما محدود: هماهنگ‌کننده GitHub مبتنی بر قواعد، برای خواندن وضعیت PR/CI و ساخت گزارش.
- هنوز ساخته نشده: Worker واقعی برای claim و اجرای صف، sandbox واقعی کدنویسی، اتصال امن مدل به ابزار توسعه، ثبت رویدادهای همه مراحل اجرا، پنل مدیریت اجرا و Local Runner آفلاین.
- هنوز فعال نشده: اجرای خودکار taskها، اصلاح خودکار کد در runtime، merge یا انتشار خودکار.
- migrationهای 0009 و 0010 روی production اجرا نشده‌اند.

## معیار پذیرش قبل از فعال‌سازی runtime

1. اجرای آزمایشی end-to-end فقط روی یک branch و یک task غیرحساس.
2. اثبات اینکه Worker نمی‌تواند main یا production را تغییر دهد.
3. اثبات جداسازی taskهای کاربران.
4. تست prompt injection و تلاش برای دسترسی به secret.
5. تست crash، lease منقضی، retry و idempotency.
6. ثبت audit event برای تمام transitionها و فراخوانی ابزار.
7. kill switch عملی و آزموده‌شده.
8. تست rollback و recovery.
9. سقف هزینه و زمان اجرا با تست منفی.
10. تأیید امنیت مستقل قبل از هر سطح دسترسی بیشتر.

## اصل نهایی

هوش‌یار باید در کارهای روزمره توسعه مستقل عمل کند، اما اختیارش محدود به محیط امن و تغییرات برگشت‌پذیر باشد. استقلال در ساخت و آزمایش؛ کنترل انسانی بر داده، امنیت، پول، قرارداد و انتشار عمومی.
