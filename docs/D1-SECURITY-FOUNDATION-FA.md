# زیرساخت پایگاه داده و کنترل سوءاستفاده

این مرحله فقط زیرساخت داده را آماده می‌کند؛ تا زمانی که APIهای ثبت‌نام/ورود و کنترل سهمیه پیاده‌سازی و آزمایش نشده‌اند، ثبت‌نام عمومی را فعال نکنید.

## ساخت D1

1. در Cloudflare Dashboard به Workers & Pages → D1 بروید.
2. دیتابیس جدیدی با نام `houshyar-ai-db` بسازید.
3. در تنظیمات Pages پروژه هوش‌یار، یک D1 binding با نام دقیق `DB` به همین دیتابیس متصل کنید.
4. فایل `migrations/0001_identity_usage_security.sql` را با Wrangler اجرا کنید:

```bash
npx wrangler d1 migrations apply houshyar-ai-db --remote
```

برای محیط محلی:

```bash
npx wrangler d1 migrations apply houshyar-ai-db --local
```

## جدول‌ها

- `users`: ایمیل نرمال‌شده، هش و salt رمز عبور، وضعیت و نقش.
- `sessions`: فقط هش توکن نشست؛ توکن خام نباید در دیتابیس ذخیره شود.
- `usage_events`: ثبت مصرف مدل و نتیجه درخواست برای سهمیه و کنترل هزینه.
- `api_rate_limits`: شمارنده‌های پنجره‌ای برای محدودیت نرخ اتمیک.
- `audit_events`: ردپای رویدادهای امنیتی و مدیریتی.

## الزامات امنیتی پیش از فعال‌سازی ورود

- هش رمز فقط با الگوریتم مقاوم و salt تصادفی مستقل (ترجیحاً PBKDF2-SHA-256 با حداقل 310,000 دور یا گزینه امن‌تر پشتیبانی‌شده)؛ رمز خام هرگز ذخیره نشود.
- توکن نشست تصادفی و پرآنتروپی تولید و فقط SHA-256 آن ذخیره شود؛ کوکی `HttpOnly; Secure; SameSite=Lax` باشد.
- انقضا، ابطال نشست، محدودیت تلاش ورود، بازیابی حساب و سیاست حذف داده باید پیاده‌سازی شوند.
- هر درخواست باید سمت سرور مجوز و سهمیه را بررسی کند؛ کنترل سمت مرورگر قابل اعتماد نیست.
- داده‌های IP و User-Agent فقط به شکل هش‌شده و با دوره نگهداری محدود ذخیره شوند.
- پاک‌سازی زمان‌بندی‌شده برای نشست‌های منقضی، rate limitهای قدیمی و داده‌های مصرف لازم است.

## وضعیت فعلی

این migration فقط ساختار را می‌سازد. تا زمان پیاده‌سازی و تست endpointها، جدول‌ها به‌تنهایی احراز هویت یا rate limiting را فعال نمی‌کنند. اتصال واقعی D1 و اجرای migration از داخل حساب Cloudflare مالک پروژه انجام می‌شود؛ هیچ کلید یا دسترسی محرمانه‌ای در Git قرار ندهید.
