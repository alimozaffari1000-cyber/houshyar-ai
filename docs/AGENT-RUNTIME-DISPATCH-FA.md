# مرز اجرای عامل‌ها — نسخه اول

## هدف
پیش از فعال‌کردن هر مصرف‌کننده صف، نوع وظیفه باید صریح و قابل اعتبارسنجی باشد. درخواست‌های متنی قدیمی کاربران به‌صورت پیش‌فرض با نوع `assistant_request` باقی می‌مانند و هرگز به‌طور خودکار اجرا نمی‌شوند.

## انواع مجاز برای اجرای محدود
- `project_health_report`
- `translation_catalog_audit`
- `agent_team_audit`

این فهرست فقط مجوز عبور از policy را تعریف می‌کند؛ هنوز Worker مصرف‌کننده صف یا اجرای زمان‌بندی‌شده ساخته/منتشر نشده است.

## ممنوع در این مرحله
- اجرای متن آزاد کاربر به‌عنوان دستور
- اجرای shell یا کد دلخواه
- تغییر فایل‌های مخزن یا شاخه اصلی
- انتشار production یا اجرای migration روی پایگاه داده فعال
- پرداخت، پیام خارجی، تغییر دسترسی یا سیاست امنیتی

## تغییر پایگاه داده
Migration شماره 0011 ستون‌های `task_type` و `payload_json` و شاخص صف را اضافه می‌کند. این migration فقط در شاخه توسعه ثبت می‌شود و روی D1 عملیاتی اجرا نشده است.

## معیار فعال‌سازی Worker در مرحله بعد
1. Worker مستقل با پیکربندی جدا از Pages.
2. claim اتمیک مبتنی بر lease و ثبت تمام رویدادها.
3. حد تلاش مجدد، timeout، kill switch و سقف مصرف.
4. آزمون جداسازی کاربران، task injection، lease منقضی‌شده و idempotency.
5. اجرای آزمایشی روی D1 جداگانه و بدون secrets تولید.
6. بررسی امنیتی و تأیید انسانی پیش از هر انتشار.
