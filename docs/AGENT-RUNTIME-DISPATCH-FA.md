# مرز اجرای عامل‌ها — نسخه اول

## قابلیت‌های پیاده‌سازی‌شده در شاخه توسعه
- نوع‌بندی وظایف و منع اجرای خودکار درخواست‌های متنی آزاد.
- API جداگانه برای ثبت سه نوع وظیفه ساختاریافته و کم‌خطر، با احراز هویت نشست، کنترل Origin و کلید idempotency.
- Worker مستقل با زمان‌بندی پنج‌دقیقه‌ای، خاموش به‌صورت پیش‌فرض و محدود به پنج وظیفه در هر نوبت.
- claim صف با lease، سقف تلاش، ثبت رویداد و خروجی گزارش‌محور.
- گزارش سلامت فقط‌خواندنی، ممیزی فهرست ۱۰۰ زبان و snapshot سیاست تیم عامل‌ها.

## انواع مجاز
- project_health_report
- translation_catalog_audit
- agent_team_audit

درخواست‌های متنی قدیمی با نوع assistant_request باقی می‌مانند و Worker آن‌ها را claim نمی‌کند.

## کنترل‌های امنیتی
- Worker shell یا کد دلخواه اجرا نمی‌کند و فایل‌های مخزن را تغییر نمی‌دهد.
- Worker به پرداخت، پیام خارجی، داده خصوصی یا عملیات production دسترسی ندارد.
- Kill switch با AGENT_RUNTIME_ENABLED=false خاموش است.
- پیکربندی D1 به دیتابیس staging مستقل اشاره می‌کند؛ شناسه دیتابیس placeholder است و باید پیش از استقرار جایگزین شود.
- Worker هنوز deploy نشده و migrationها روی D1 فعال اجرا نشده‌اند.

## گام‌های پیش از فعال‌سازی
1. اجرای migrationهای 0009 تا 0011 روی D1 آزمایشی مجزا.
2. جایگزینی شناسه staging در wrangler.agent-runtime.toml.
3. اجرای تست یکپارچه claim/lease/idempotency و جداسازی کاربران.
4. بازبینی امنیتی و بررسی لاگ‌ها.
5. فعال‌سازی کنترل‌شده فقط در محیط staging.

این نسخه عامل خودتوسعه‌دهنده کد نیست؛ مصرف‌کننده صف محدود برای گزارش‌ها و ممیزی‌های قطعی است.
