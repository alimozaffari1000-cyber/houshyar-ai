# پیاده‌سازی مرحله اول خرید محلی

این تغییر اولین لایه اجرایی دستیار خرید محلی است؛ هنوز اتصال به نقشه، پرداخت یا سفارش‌گذاری درون هوش‌یار فعال نمی‌شود.

## API جست‌وجوی عمومی

`GET /api/stores`

پارامترها:
- `q`: نام کالا یا عبارت جست‌وجو
- `city` و `region`: محدودکردن نتایج به شهر و استان/منطقه
- `mode=delivery` یا `mode=pickup`: فیلتر روش دریافت
- `lat` و `lon`: مختصات اختیاری برای مرتب‌سازی بر اساس فاصله؛ باید هر دو ارسال شوند و فقط پس از کلیک کاربر روی «نزدیک من» از مرورگر گرفته می‌شوند.\n- `limit` و `offset`: صفحه‌بندی نتایج؛ حداکثر ۵۰ مورد در هر صفحه. برای کنترل هزینه، API حداکثر ۵۰۰ نامزد اخیر را مرتب می‌کند و در صورت عبور از این سقف، `truncated: true` برمی‌گرداند.

فقط محصول منتشرشده از فروشگاه فعال نمایش داده می‌شود. موجودی و قیمت از داده فعلی فروشنده می‌آید؛ این نسخه هنوز اتصال لحظه‌ای POS یا تأیید مستقل موجودی ندارد. فاصله فقط برای همان درخواست محاسبه می‌شود و مختصات جست‌وجو ذخیره نمی‌شود. رابط بازارگاه فیلتر شهر، ارسال به منزل، دریافت حضوری و دکمه اختیاری «نزدیک من» دارد؛ لینک سفارش فقط در صورت HTTPS نمایش داده می‌شود. نتایج محدودشده با پیام شفاف اعلام می‌شوند.

## تنظیمات فروشنده

`PUT /api/store/profile`

فروشنده واردشده می‌تواند شهر، منطقه، نشانی عمومی کسب‌وکار، مختصات محل فروشگاه، تحویل در منزل، دریافت حضوری، تلفن و لینک سفارش HTTPS را به‌روزرسانی کند. کنترل مالکیت فروشگاه سمت سرور انجام می‌شود.

مختصات این بخش مربوط به محل عمومی کسب‌وکار است، نه نشانی مشتری.

## تغییر دیتابیس

Migration `0006_local_store_discovery.sql` فقط ستون‌های لازم را به `merchant_stores` اضافه می‌کند. هیچ migration راه‌دوری اجرا نشده است. ابتدا باید وضعیت migrationهای D1 در staging بررسی و این migration در staging آزمایش شود.

## محدودیت‌های این مرحله

- نقشه و مسیریابی هنوز متصل نیست.
- پرداخت، سبد خرید و ثبت سفارش هنوز وجود ندارد.
- ساعت کاری و باز/بسته‌بودن زنده هنوز پشتیبانی نمی‌شود.
- فروشگاه‌های خارج از هوش‌یار فقط از طریق لینک یا اطلاعات عمومیِ مجاز قابل معرفی خواهند بود؛ این PR scraping انجام نمی‌دهد.
