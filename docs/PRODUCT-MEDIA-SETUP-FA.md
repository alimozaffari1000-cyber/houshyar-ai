# راه‌اندازی امن تصاویر محصولات فروشندگان

## وضعیت
API مدیریت تصویر محصول در مسیر `/api/store/products/media` پیاده‌سازی شده است. این endpoint فقط برای فروشنده احرازشده با فروشگاه فعال و فقط برای محصول متعلق به همان فروشگاه کار می‌کند.

## Binding موردنیاز Cloudflare
یک R2 bucket خصوصی بسازید و در تنظیمات Pages/Workers هر دو محیط Production و Preview این binding را تعریف کنید:

- Binding name: `MEDIA_BUCKET`
- Bucket: یک bucket خصوصی اختصاصی برای فایل‌های رسانه‌ای هوش‌یار، برای نمونه `houshyar-ai-media`
- Public Development URL / r2.dev: خاموش بماند؛ فایل‌ها نباید با URL عمومی در دسترس باشند.

این مخزن به حساب Cloudflare شما دسترسی تنظیماتی ندارد؛ بنابراین binding یا bucket را از راه دور ایجاد نکرده است. تا زمان تنظیم binding، API عمداً با `503 MEDIA_STORAGE_NOT_CONFIGURED` بسته می‌ماند.

## API
### بارگذاری
`POST /api/store/products/media` با `multipart/form-data`:
- `productId`: شناسه UUID محصول
- `file`: تصویر JPEG، PNG یا WebP، حداکثر ۵ مگابایت

سرور امضای واقعی فایل را بررسی می‌کند، ابعاد تصویر را استخراج و محدود می‌کند، کلید تصادفی می‌سازد و فایل را در R2 خصوصی می‌گذارد. فقط فراداده در D1 ذخیره می‌شود. هیچ URL عمومی به مرورگر بازگردانده نمی‌شود.

### حذف
`DELETE /api/store/products/media` با JSON:
`{ "mediaId": "..." }`

حذف فقط برای مالک فروشگاه مجاز است. در صورت نیاز به پاک‌سازی فایل‌های یتیم R2، باید job دوره‌ای تطبیق کلیدهای R2 با ردیف‌های D1 اضافه شود.

## Migration
جدول `product_media` در migration شماره 0005 تعریف شده است. قبل از استفاده در محیط واقعی، تاریخچه migrationهای remote را بررسی و migration را ابتدا روی staging اعمال کنید. این تغییرات migration راه‌دور را اجرا نمی‌کنند.

## محدودیت فعلی
این API فقط بارگذاری و حذف امن تصویر محصول فروشنده را آماده می‌کند. رابط مدیریت گالری فروشنده، نمایش امن/بهینه تصویر در کاتالوگ، پردازش تصویر هوش مصنوعی و تجربهٔ واقعی try-on هنوز جداگانه باید ساخته و آزمایش شوند. عکس شخصی خریدار در نسخه فعلی همچنان فقط در مرورگر پیش‌نمایش می‌شود و به این endpoint ارسال نمی‌شود.
