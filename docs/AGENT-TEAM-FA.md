# تیم ایجنت‌های هوش‌یار

این سند مرجع مسئولیت‌ها و مرزهای اختیار ایجنت‌های پروژه است. ایجنت‌ها ابزارهای کنترل و اتوماسیون توسعه‌اند؛ وجود آن‌ها به معنی داشتن یک عامل مستقل با دسترسی نامحدود یا نظارت دائمی بر سرویس زنده نیست.

## ساختار تیم

| ایجنت | مسئولیت | اختیار و محدودیت |
|---|---|---|
| مدیر محصول و هماهنگ‌کننده | تبدیل قابلیت‌های جدید به ماژول، وابستگی، معیار پذیرش و برنامه انتشار | پیشنهاد و گزارش؛ بدون ادغام یا انتشار خودکار |
| ایجنت یکپارچگی محصول | اجرای کنترل‌های ساختار، تست، build، کیفیت و امنیت در یک گزارش واحد | فقط بررسی مخزن و CI؛ بدون تغییر داده زنده |
| ایجنت کیفیت و کارایی | تست خودکار، build و بودجه حجم/کیفیت | گزارش خطا؛ بدون تغییر خودکار منطق تجاری |
| ایجنت امنیت | اسکن الگوهای افشای راز، وابستگی‌ها و تست‌ها | هشدار؛ بدون دسترسی به secretهای محیط |
| ایجنت نگهبان ساختار | بررسی پیش‌نیازهای ساختار پروژه و تنظیمات انتشار | اصلاحات محدود فقط در اسکریپت تعمیر مجاز؛ نیازمند بازبینی انسانی |
| ایجنت آزمون قابلیت | پوشش تست برای هر ماژول جدید و مسیرهای بین‌ماژولی | تست و گزارش؛ بدون تأیید خودکار انتشار |

## ماژول‌هایی که باید در ارزیابی یکپارچگی دیده شوند

1. هسته گفتگو و اتصال ارائه‌دهندگان مدل
2. حساب کاربری، نشست، مجوزها و سهمیه مصرف
3. استودیو تولید محتوا و تصویر
4. فروشگاه‌ساز و پرو مجازی پوشاک
5. بازار آگهی‌ها و فروشگاه‌های محلی کشورمحور
6. سفارش، پرداخت، بازپرداخت، اختلاف و تسویه
7. چندزبانگی، ارز، منطقه زمانی و بومی‌سازی
8. پنل فروشنده و پنل مدیریت
9. زیرساخت، پایگاه داده، ذخیره‌سازی فایل و مشاهده‌پذیری

## قرارداد افزودن قابلیت جدید

هر قابلیت جدید باید پیش از ادغام، این موارد را مشخص کند:

- مالک ماژول و وابستگی‌هایش
- مسیرهای API و قرارداد ورودی/خروجی
- احراز هویت، مجوز، محدودیت نرخ و مالکیت داده
- مدل داده و migration برگشت‌پذیر یا برنامه بازیابی
- حالت‌های بارگذاری، خطا، خالی و دسترس‌پذیری رابط
- تست واحد، تست API و تست تعامل با ماژول‌های وابسته
- ترجمه‌ها، ارز/کشور و الزامات حریم خصوصی
- هزینه عملیاتی، محدودیت مصرف و ریسک امنیتی
- وضعیت انتشار: آزمایشی، آماده بررسی، یا فعال در تولید

## قواعد ایمنی و انتشار

- ایجنت‌ها نباید بدون تأیید مالک، pull request را merge یا سایت production را deploy کنند.
- هیچ ایجنتی نباید secret، توکن پرداخت، کلید خصوصی یا داده شخصی را در log یا issue منتشر کند.
- migration روی پایگاه داده واقعی فقط پس از پشتیبان‌گیری و تأیید مالک اجرا می‌شود.
- فعال‌سازی پرداخت یا بازار در هر کشور منوط به بررسی حقوقی، مالیاتی، احراز هویت و امکان تسویه همان کشور است.
- داده‌های بازارهای دیگر (از جمله دیوار و شیپور) بدون مجوز نباید کپی یا scrape شوند.
- شکست یک workflow به معنی هک‌شدن یا خرابی production نیست؛ ابتدا باید log و محیط اجرا بررسی شود.

## حدود فعلی

ایجنت یکپارچگی در GitHub Actions اجرا می‌شود: هنگام pull request، push به main و شاخه‌های feature، اجرای دستی و یک‌بار در هفته. بررسی آن شامل اسکریپت ساختار، تست‌ها، build، ممیزی کیفیت، اسکن secret و audit وابستگی‌هاست. این ایجنت Cloudflare D1، دامنه، پرداخت زنده، تجربه واقعی مرورگر یا عملکرد production را از داخل GitHub تأیید نمی‌کند.
