# سند مادر معماری و نقشه جامع هوش‌یار
نسخه: 1.0  
تاریخ: 2026-11-18  
وضعیت: سند طراحی و برنامه اجرایی؛ قابلیت‌ها فقط در صورت وجود پیاده‌سازی و استقرار تأییدشده، «فعال» محسوب می‌شوند.

## 1. چشم‌انداز و اصول بنیادین

هوش‌یار یک اکوسیستم جهانی هوش مصنوعی برای افراد، متخصصان، کسب‌وکارها، توسعه‌دهندگان و سازمان‌هاست. هدف آن آسان‌ترکردن زندگی و کار، اتصال عرضه و تقاضا، ترجمه و ارتباط میان زبان‌ها، افزایش بهره‌وری و فراهم‌کردن ابزار ساخت و عرضه خدمات دیجیتال است.

اصول غیرقابل مذاکره:
- طراحی جهانی با بومی‌سازی کشورمحور؛ نه فرض یکسان‌بودن قوانین، پول، مالیات یا روش پرداخت کشورها.
- معماری ماژولار، API-first، قابل تعویض و توسعه تدریجی.
- حریم خصوصی از ابتدا، کمینه‌سازی داده و رضایت روشن کاربر.
- دسترسی مبتنی بر نقش و مجوز؛ جداسازی کامل داده‌های کاربران و سازمان‌ها.
- عامل‌های هوش مصنوعی محدود به ابزارها و دامنه مجاز؛ عملیات حساس با تأیید انسانی.
- شفافیت منبع، تاریخ، سطح اطمینان و محدودیت پاسخ در اطلاعات حساس یا متغیر.
- آزمون، پایش، ثبت رویداد، پشتیبان‌گیری و امکان بازگشت نسخه.
- عدم ادعای فعال‌بودن قابلیتی که صرفاً طراحی یا مستندسازی شده است.

## 2. معماری کلان

### 2.1 لایه‌های اصلی
1. تجربه کاربری: وب‌اپلیکیشن موبایل‌محور، PWA، پنل فردی، پنل سازمانی و پنل توسعه‌دهنده.
2. هویت و دسترسی: حساب، نشست، MFA در صورت پشتیبانی، نقش‌ها، مجوزها، رضایت‌ها و جداسازی tenant.
3. درگاه API: نسخه‌بندی، احراز هویت، rate limit، quota، idempotency، اعتبارسنجی ورودی و ثبت درخواست.
4. Houshyar Core: تشخیص قصد، ارکستراسیون مدل، انتخاب ابزار، مدیریت عامل، کنترل هزینه و کنترل کیفیت.
5. سرویس‌های دامنه: ترجمه، تجارت، بازار خدمات، کسب‌وکار، آموزش، سلامت، کشاورزی و سایر حوزه‌ها.
6. داده و دانش: پایگاه داده عملیاتی، فایل، cache، صف، جست‌وجو و دانش مستند.
7. اعتماد و ایمنی: ضدتقلب، پایش امنیت، کنترل محتوا، ثبت ممیزی و مدیریت اختلاف.
8. یکپارچه‌سازی: اتصال سرویس‌های بیرونی، webhook، رویدادها و SDK.
9. عملیات: CI/CD، مشاهده‌پذیری، مدیریت خطا، backup، بازیابی و rollback.

### 2.2 معماری پیشنهادی روی Cloudflare
- Cloudflare Pages: رابط وب و دارایی‌های فرانت‌اند.
- Pages Functions یا Workers: API و منطق سمت سرور؛ انتخاب نهایی بر اساس ساختار فعلی مخزن.
- D1: داده‌های رابطه‌ای اولیه.
- R2: فایل‌ها و اسناد.
- KV: cache و تنظیمات غیرحساس مناسب.
- Queues: کارهای پس‌زمینه و پردازش غیرهمزمان.
- Durable Objects: هماهنگی stateful یا ارتباط زنده در صورت نیاز واقعی.
- Secrets: نگهداری کلیدهای سرویس فقط سمت سرور.
- سرویس هوش مصنوعی از طریق adapter مستقل تا ارائه‌دهنده قابل تعویض باشد.

نباید فناوری جدیدی صرفاً به‌خاطر جذابیت اضافه شود. ابتدا قابلیت‌های موجود مخزن بررسی و سپس انتخاب معماری تثبیت شود.

## 3. Houshyar Core و مدیریت عامل‌ها

### 3.1 اجزای هسته
- Request Intelligence: تشخیص زبان، قصد، حوزه، فوریت و محدودیت.
- AI Orchestrator: انتخاب مدل، ابزار و مسیر انجام کار.
- Agent Manager: ثبت، نسخه‌بندی، اجرا و توقف عامل‌ها.
- Tool Registry: فهرست ابزارهای مجاز و قرارداد ورودی/خروجی.
- Context & Memory: حافظه با رضایت، محدوده و سیاست نگهداری.
- Cost Controller: سقف هزینه و انتخاب مدل متناسب.
- Quality Monitor: ارزیابی خروجی، خطا و رضایت.
- Policy Engine: بررسی مجوز پیش از هر اقدام.

### 3.2 عامل‌های تخصصی
عامل اصلی هماهنگ‌کننده، توسعه، آزمایش، امنیت، کیفیت و عملکرد، تحقیق، ترجمه، تجارت، پشتیبانی، بازاریابی، مدیریت کسب‌وکار و عامل‌های تخصصی هر محصول.

### 3.3 سطوح اختیار
- سطح A: مشاهده، تحلیل و گزارش.
- سطح B: پیشنهاد و آماده‌سازی اقدام برای تأیید.
- سطح C: اجرای محدود و برگشت‌پذیر در محدوده مجوز از پیش تعیین‌شده.
پرداخت، انتقال دارایی، امضای قرارداد، حذف داده، تغییر دسترسی، انتشار عمومی، تغییر تنظیمات امنیتی و عملیات حقوقی حساس نیازمند تأیید انسانی صریح است.

### 3.4 موتور خودتوسعه و اجرای طرح‌ها
مشخصات تفصیلی چرخه خودتوسعه، سطوح خودمختاری، کنترل‌های اجرایی و معیارهای پذیرش در سند [موتور خودتوسعه هوش‌یار](./SELF-DEVELOPMENT-ENGINE-FA.md) ثبت شده است. هدف، اجرای مستقل توسعه در محیط sandbox و branch ایزوله و تولید PR قابل بازبینی است؛ نه تغییر مستقیم main یا production.

## 3.4 خودترمیم و به‌روزرسانی
پایش → تشخیص → پیشنهاد اصلاح → ساخت شاخه/محیط آزمایشی → آزمون → بررسی امنیتی → تأیید انسانی → انتشار مرحله‌ای → پایش → rollback در صورت شکست.
عامل‌ها نباید مستقیم و بی‌نظارت روی production تغییر اعمال کنند.

## 10. Houshyar Payment & Settlement
یک Payment Router برای انتخاب روش پرداخت متناسب با کشور، ارز، قانون، کارمزد، زمان تسویه و ریسک.
روش‌ها: پرداخت بانکی/کارتی محلی از PSP مجاز و دارایی‌های دیجیتال در صورت مجازبودن و پشتیبانی ارائه‌دهنده.
دارایی‌ها و شبکه‌های مورد بررسی، نه وعده پشتیبانی قطعی: USDT، USDC، XRP/XRPL، TRON، Monero، Stellar، EURC، RLUSD، PYUSD و Bitcoin/Lightning. دارایی و شبکه باید جداگانه مشخص شوند.
اجزا: quote، payment order، provider adapter، webhook verification، refund، dispute، settlement، reconciliation و audit.
قواعد:
- هوش‌یار بدون مجوز، وجوه مشتری را نگهداری یا انتقال نمی‌دهد.
- wallet در نسخه اول می‌تواند صرفاً داشبورد اطلاعاتی ارائه‌دهنده مجاز باشد.
- escrow فقط از شریک دارای مجوز و قرارداد روشن.
- موفقیت پرداخت فقط با webhook معتبر و امضاشده/استعلام سرور تأیید شود، نه redirect مرورگر.
- KYC/AML، sanctions، Travel Rule و محدودیت جغرافیایی بر اساس قانون و ارائه‌دهنده.
- انتخاب درگاه نهایی بعد از تعیین کشور ثبت شرکت، بازار هدف و نظر حقوقی.
- کلید خصوصی کیف پول هرگز در فرانت‌اند یا مخزن کد قرار نگیرد.

## 27. قراردادهای فنی مشترک
- همه APIها با prefix نسخه‌دار مانند /api/v1.
- خطاهای استاندارد، schema validation و محدودیت اندازه.
- idempotency برای عملیات حساس و webhookها.
- correlation ID و log ساختاریافته بدون اطلاعات محرمانه.
- pagination و فیلتر امن.
- timestamp استاندارد و ذخیره UTC؛ نمایش بر اساس منطقه کاربر.
- currency و locale صریح؛ هرگز فرض واحد پیش‌فرض در معامله.
- webhook با امضا، timestamp، replay protection و retry.
- migration نسخه‌دار و backup قبل از production.
- feature flag برای rollout تدریجی.
