# ماژول قرعه‌کشی هوش‌یار

وضعیت: زیرساخت اولیه در شاخه توسعه؛ فروش بلیت، دریافت وجه و پرداخت جایزه فعال نیست.

## تصمیم محصول
- فاز نخست فقط قرعه‌کشی تبلیغاتی رایگان است؛ شرکت‌کننده برای ورود وجهی نمی‌پردازد.
- حالت paid_licensed صرفاً یک حالت آینده‌نگر در مدل داده است. فیلد paid_entry_enabled با قید دیتابیس همیشه صفر است و هیچ API پرداخت/فروش بلیت برای آن وجود ندارد.
- قبل از هر عرضه پولی باید مجوز معتبر، نظر حقوقی هر کشور، احراز سن/هویت در صورت الزام، محدودیت جغرافیایی، provider مجاز، حفاظت وجوه و فرایند شکایت/بازپرداخت فراهم شود.
- استخرهای کشورها و ارزها هرگز با هم ادغام نمی‌شوند. این قاعده در طراحی نسخه پولی آینده الزامی است، اما فعلاً هیچ استخر مالی ایجاد نمی‌شود.

## تجربه کاربر و شفافیت
صفحه هر دوره باید عنوان و قوانین نسخه‌دار، کشور مجاز، زمان شروع/پایان/قرعه‌کشی با timezone، شرح جایزه، سقف ورودی، تعداد شرکت‌کنندگان یکتا، تعداد بلیت واجد شرایط و وضعیت دوره را نشان دهد. ارقام عمومی فقط از داده‌های معتبر سمت سرور خوانده می‌شوند.
هر کاربر در فاز اول حداکثر یک ورودی برای هر دوره دارد؛ محدودیت قابل تنظیم است ولی نباید دور زده شود. ثبت ورودی idempotent خواهد بود و ticket code غیرقابل حدس تولید می‌شود.
نتیجه شامل شناسه دوره، تعداد ورودی‌های واجد شرایط، نسخه الگوریتم، تعهد رمزنگاری entropy پیش از قرعه‌کشی، داده لازم برای بازتولید انتخاب و رکورد حسابرسی است. اطلاعات شخصی برنده بدون رضایت منتشر نمی‌شود.

## انتخاب برنده و ضدتقلب
- انتخاب باید در سمت سرور و با CSPRNG انجام شود؛ از Math.random یا زمان سیستم به‌عنوان منبع تصادفی استفاده نشود.
- انتخاب یکنواخت با rejection sampling انجام می‌شود تا modulo bias حذف شود.
- فهرست ورودی‌ها پیش از قرعه‌کشی snapshot و مرتب‌سازی پایدار می‌شود؛ ورودی تکراری، خوددعوتی یا نامعتبر حذف می‌شود.
- ثبت نتیجه و تغییر وضعیت دوره باید در یک تراکنش اتمیک انجام شود.
- نتایج و audit log غیرقابل ویرایش/حذف هستند؛ اصلاح با رویداد جدید و دلیل ثبت‌شده انجام می‌شود.
- RNG، commitment/reveal و الگوریتم باید توسط بازبین مستقل قابل راستی‌آزمایی باشند؛ پیاده‌سازی فعلی فقط موتور انتخاب پایه و schema است و هنوز پروتکل کامل public-verifiable را پیاده نکرده است.

## مدل داده
- draw_campaigns: قوانین، زمان‌بندی، جایزه، کشور، وضعیت، سقف ورودی و گیت غیرفعال پرداخت.
- draw_entries: ورودی یکتا، کد بلیت و وضعیت واجد شرایط بودن.
- draw_results: یک نتیجه برای هر دوره، ورودی برنده، نسخه الگوریتم و داده راستی‌آزمایی.
- draw_audit_events: رخدادهای مدیریتی و عملیاتی append-only.
